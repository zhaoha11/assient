# 本地播放功能

状态：阶段一、阶段 2.1～2.3、阶段 3.1、阶段 3.3～3.6 的代码链路已实施。远程 `AVPlayer` 与本地 `LocalPlayer` 已解耦；本地播放接入 Qt Multimedia，并实现打开、播放控制、视频显示、定位、进度、音量、倍速和中文错误提示。完整客户端中的各项播放和生命周期场景仍待手动验收。

## 文档目的

为 ECloudAssistant 客户端逐步增加本地媒体播放功能，并记录各阶段的目标、关键做法、验证结果和剩余工作。

## 统一边界与注意事项

- 保留 `LocalPlayerWgt` 作为独立的本地播放器页面，不嵌入 `PullerWgt`，也不直接照搬耦合了 `SigConnection` 和远程输入事件的完整 `AVPlayer`。
- 远程实时流继续使用现有 `AVPlayer + SigConnection + AVDEMuxer + Decoder + OpenGLRender/AudioRender` 链路，本地文件播放使用 Qt Multimedia，两条链路不互相侵入。
- 不修改远程控制、设备列表、高级设置、远程监控、信令或 RTMP 数据流程。
- 播放器保留打开文件、播放/暂停、停止、进度、当前时间/总时长、音量和倍速等基础控件；暂不增加最近播放、播放列表和复杂文件信息。
- 自适应布局统一使用 Qt Layout 和 `QSizePolicy`，不使用固定坐标，也不设置固定视频尺寸。
- 每个已实施阶段都需要通过 Debug 编译、链接和 `git diff --check`；完整客户端中的导航、缩放和交互效果仍需手动验证。
- 本地播放不再计划自建 `PlayerCore`、改造 `AVDEMuxer`、编写本地音视频解码器或自行实现 A/V Sync、播放时钟。

## 阶段三：Qt Multimedia 本地播放

### 最终架构

```text
远程监控：PullerWgt → AVPlayer → SigConnection / AVDEMuxer / Decoder
                                  → OpenGLRender / AudioRender

本地播放：LocalPlayerWgt → LocalPlayer → QMediaPlayer
                                      ├─ QAudioOutput
                                      └─ QVideoWidget
```

核心原则：`LocalPlayerWgt` 只负责界面和用户操作；`LocalPlayer` 封装全部 Qt Multimedia API、播放状态、进度和错误；远程 `AVPlayer` 继续保持现有自研 RTMP 播放与远控职责。

### 取消的旧计划

- 不创建 `PlayerCore.h/.cpp`。
- 不对现有 `AVDEMuxer` 做本地文件改造。
- 不为本地播放编写视频 Decoder、音频 Decoder、播放线程、A/V Sync 或播放时钟。
- 不让 `LocalPlayerWgt` 直接到处调用 `QMediaPlayer`、`QAudioOutput`，避免 UI 与后端耦合。

### 最终文件职责

```text
ECloudAssistant/
├─ Player/
│  ├─ LocalPlayer.h/.cpp     # Qt Multimedia 本地播放业务封装
│  └─ Player.pri
├─ Puller/UI/AVPlayer.h/.cpp # 远程实时流、信令和远控
└─ UI/center/LocalPlayerWgt.h/.cpp # 本地播放界面
```

### 阶段 3.4：打开文件与视频显示

状态：已实施（2026-09-29）。Debug 编译、链接与 `git diff --check` 通过；真实文件播放效果待在完整客户端中手动验证。阶段 3.5～3.6 尚未实施。

目标：打通 `QFileDialog → LocalPlayer::Open(path) → QMediaPlayer::setSource()`，并将 `QVideoWidget` 放入现有视频区域，通过 `setVideoOutput()` 显示真实画面。

状态规则：

```text
Idle ──Open(path)──> Opening ──QMediaPlayer 加载成功──> Stopped
                              └─加载或格式失败────────> Error
```

文件不存在、格式不支持、媒体解析失败和资源错误统一由 `LocalPlayer` 转换为中文错误信息，再通知 `LocalPlayerWgt`；UI 不直接处理 Qt Multimedia 底层错误。

实施结果：

- `LocalPlayer` 持有 `QVideoWidget`，构造时 `setVideoOutput()` 接入；通过 `videoWidget()` 把控件交给界面放入自己的布局，界面不直接接触 `QMediaPlayer`。
- `LocalPlayer::Open(path)` 先校验文件存在，不存在时进入 `Error` 并上报“文件不存在：…”，否则进入 `Opening` 并 `setSource(QUrl::fromLocalFile(...))`。
- 状态由底层驱动：`mediaStatusChanged == LoadedMedia` 时由 `Opening` 进入 `Stopped`；`errorOccurred` 时进入 `Error`，并把 `ResourceError/FormatError/NetworkError/AccessDeniedError` 映射为中文提示由 `sig_errorOccurred` 上报。`StoppedState` 只在真实播放/暂停时收敛，不再覆盖 `Opening` 和 `Error`。
- `LocalPlayerWgt` 的视频区改为 `QStackedWidget` 双页：默认显示“尚未打开文件”空状态，打开后切到 `QVideoWidget` 画面；打开失败时切回空状态并把中文错误显示在说明文字上。
- 新增“打开文件”按钮回调，使用 `QFileDialog::getOpenFileName` 选择媒体文件，带常见音视频扩展名过滤。

### 阶段 3.5：基本播放与进度

状态：已实施（2026-09-29），含三项后续修复与增强（暂停进度保持、打开即显示首帧、裁剪铺满消除黑边，见下）。Debug 编译、链接与 `git diff --check` 通过；播放进度与时间文本的实际观感待在完整客户端中手动验证。

目标：打通播放、暂停、停止按钮，并同步 `position`、`duration`、时间文本和进度条。

调用关系：

```text
LocalPlayerWgt → LocalPlayer::Play/Pause/Stop
               → QMediaPlayer::play/pause/stop

QMediaPlayer::positionChanged/durationChanged
               → LocalPlayer
               → LocalPlayerWgt 更新进度和时间
```

按钮文字和 enabled 状态必须来自 `QMediaPlayer` 的真实状态，而不是 UI 中分散维护的布尔值。

实施结果：

- `LocalPlayer` 直接转发 `QMediaPlayer::positionChanged/durationChanged`，缓存为 `position_`/`duration_` 并通过 `position()`/`duration()` 暴露，界面不直接读取 `QMediaPlayer`。
- `positionChanged` 处理器带守卫：位置为 `0` 且底层不处于 `QMediaPlayer::StoppedState` 时忽略该次上报。判断读 `mediaPlayer_->playbackState()` 而非业务状态缓存，以兼容信号先后的两种顺序；停止与打开新文件仍会正常归零。
- `LocalPlayer::Open(path)` 在加载前先重置时间轴（`position_ = duration_ = 0` 并补发一次信号），避免新文件加载前残留上一个文件的位置和时长。
- `LocalPlayerWgt` 的 `timeLabel_` 改为成员，新增 `updateTimeline()`：按 `position/duration` 换算进度条千分位值（`duration > 0` 时 `position * 1000 / duration`），并用 `formatDuration()` 把毫秒格式化为 `mm:ss`（超过一小时为 `h:mm:ss`）拼成 `当前 / 总长`。
- `applyLocalPlaybackState()` 在每次状态变化时一并调用 `updateTimeline()`，保证状态与时间轴同帧刷新；播放/暂停按钮文字与 enabled 仍全部由 `player_` 的真实状态推导。
- 进度条在阶段 3.5 只作显示：`setAttribute(Qt::WA_TransparentForMouseEvents)` 屏蔽拖动，外观仍按 `hasMedia` 切换可用样式；真正的拖动定位留给阶段 3.6 的 `Seek()`。
- 首帧预览：`LocalPlayer` 订阅 `videoWidget_->videoSink()` 的 `videoFrameChanged`，`LoadedMedia` 后先 `play()` 解码首帧、收到首帧立即 `pause()`，实现“打开文件即显示第一帧、点击播放才播放”；预览期间的 `PlayingState` 不对外暴露，避免播放按钮闪烁。
- 裁剪铺满：`videoWidget_->setAspectRatioMode(Qt::KeepAspectRatioByExpanding)`，视频按比例放大到铺满整个控件、超出部分裁掉，消除上下或左右的黑色留边；代价是最外圈画面被裁切。

#### 3.5 后续修复与增强

以下三条都是在阶段 3.5 验收过程中发现并就地修复的，均只改 `ECloudAssistant/Player/LocalPlayer.{h,cpp}`，不涉及界面、QSS、协议或服务端。

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 暂停后进度条归零（总时长仍正确） | Qt 媒体后端在切到暂停的瞬间上报一次瞬时 `positionChanged(0)`，`updateTimeline()` 如实渲染 | `positionChanged` 处理器加守卫：仅当底层处于 `StoppedState` 时才接受 `0` |
| 打开文件后视频区全黑，只有点播放才出画面 | `LoadedMedia` 只完成加载、不解码首帧，控件无内容可显示 | 订阅 `videoSink()->videoFrameChanged`，加载完成后 `play()` 抢解码，首帧到达立即 `pause()` 定格 |
| 视频画面上下或左右存在黑色留边 | `QVideoWidget` 默认 `Qt::KeepAspectRatio`，源比例与控件比例不一致时留空并涂黑 | `setAspectRatioMode(Qt::KeepAspectRatioByExpanding)`，按比例放大铺满后裁掉溢出部分 |

验证：三次修改后各自完成 Debug 编译链接（`LocalPlayer.o` 重新编译、`debug/ECloudAssistant.exe` 重新链接）与 `git diff --check`；暂停保持、打开即出首帧、黑边消失三项表现仍需在完整客户端中手动确认。

取舍说明：

- 首帧预览期间 `play()` 在音频未静音的状态下执行，个别后端可能出现极短的音频爆音；预览结束后播放器停在 `Paused`，界面按“媒体可用”处理，播放按钮可用且文字为“播放”。
- 裁剪铺满会让最外圈画面被裁掉，若源视频边缘带 OSD 时间戳、字幕或录屏任务栏需要留意；替代方案为 `Qt::IgnoreAspectRatio`（拉伸、会变形）或保持 `Qt::KeepAspectRatio`（保留黑边），均可一行切换。
- 填充方式当前为编译期固定值，未提供界面切换；若后续需要“适应/铺满/裁剪”三态切换或自定义背景色，则要改用 `QVideoSink` 收帧后自绘，代价明显更大。

### 阶段 3.6：Seek、音量、倍速、错误与生命周期

状态：已实施（2026-09-29）。Debug 编译、链接与 `git diff --check` 通过；拖动定位、音量、倍速与生命周期表现待在完整客户端中手动验证。

目标：完成 `Seek()`、`SetVolume()`、`SetPlaybackRate()`，并完善错误反馈、关闭页面和重新打开文件的资源管理。

控件映射：

- 进度条拖动 → `LocalPlayer::Seek()` → `QMediaPlayer::setPosition()`。
- 音量滑块 → `LocalPlayer::SetVolume()` → `QAudioOutput::setVolume()`。
- 倍速选择 → `LocalPlayer::SetPlaybackRate()` → `QMediaPlayer::setPlaybackRate()`。

实施结果：

- `LocalPlayer` 新增四个接口：`Seek(qint64)`、`SetVolume(float)`、`SetPlaybackRate(qreal)`、`Close()`。前三者只做参数校验后转发，界面继续不接触 `QMediaPlayer`/`QAudioOutput`。
- `Seek()` 先用缓存的总时长把目标位置截断到 `0～duration_`，把结果写回 `position_` 并立刻补发一次 `sig_positionChanged`，最后才调用 `setPosition()`。这样界面无需等待后端确认就能看到定位结果，也避免“拖动到最左端”时后端上报的 `positionChanged(0)` 被零值守卫丢弃后滑块回弹。总时长为 0 时直接忽略。
- `SetVolume()` 把入参截断到 `0.0～1.0` 后写入 `QAudioOutput`。
- `SetPlaybackRate()` 直接转发；倍率取自下拉框的 `itemData`（档位文本与倍率一起写入），界面不解析 `"1.5x"` 这类文本。
- `Close()` 先切回 `Idle` 再 `stop()`、`setSource(QUrl())` 并重置时间轴：先切状态可避免 `stop()` 触发的 `StoppedState` 把已关闭的媒体重新标记为可播放；空源让 Qt Multimedia 释放当前文件与解码资源，杜绝残留旧文件的声音。`LocalPlayerWgt` 在 `hideEvent`（过滤 `spontaneous()`，即离开页面而非系统最小化）与析构函数中都调用它，覆盖切页、退出与页面销毁场景。
- 错误反馈补齐兜底：`mediaStatusChanged == InvalidMedia` 且仍处于 `Opening` 时进入 `Error` 并上报“无法识别该媒体文件”，避免加载失败却永远停在“加载中”；若随后 `errorOccurred` 到达，会用更具体的中文提示覆盖该兜底文案。
- 进度条交互：去掉阶段 3.5 用于屏蔽拖动的 `WA_TransparentForMouseEvents`，改为 `sliderPressed`/`sliderMoved`/`sliderReleased` 三件套。拖动期间 `seeking_` 置位，`updateTimeline()` 转而以滑块值为唯一依据刷新时间文本，滑块不被后端回发拉回；松开时统一提交一次 `Seek()`，避免拖动过程中反复定位。
- 键盘方向键与点击滑槽只改变滑块数值、不触发 `sliderMoved`，因此另接 `valueChanged`：用 `updatingSlider_` 标记区分“后端回填”与“用户操作”，只对后者发起定位——否则播放中的每一次位置回填都会反过来触发一次 `setPosition()`。
- 音量滑块（0～100）用 `valueChanged` 换算成 `0.0～1.0` 的线性音量并写入后端；构造完成后再同步一次初始值，保证后端音量与界面显示的 80 一致。倍速同理接在 `currentIndexChanged` 上。
- `applyLocalPlaybackState()` 在媒体不可用时额外复位 `seeking_` 并抬起滑块，避免 `Close()` 或错误发生时残留“拖动中”状态把时间文本卡在预览分支；`seekFromSlider()` 也会在进度条被禁用时直接返回。
- 结构性整理：`LocalPlayerWgt` 构造函数拆成 `buildVideoArea()`、`buildControlBar()`、`bindPlayerSignals()` 三段——前两者返回控件交由页面根布局，第三者只做信号接通与音量/倍速初始值同步。构造函数只保留“建后端 → 组装布局 → 接线 → 首次刷新”四步，纯结构调整、无行为变化。

生命周期验收：打开 A 后播放/停止并打开 B、播放中打开 B、关闭并重新进入页面、反复播放/停止，均不得崩溃、残留旧文件声音或产生错误状态和错误进度。

代码层面已处理：`Open()` 在 `setSource()` 前重置时间轴，`setSource()` 切换媒体源；`Close()` 负责退出与销毁时的资源释放；`StoppedState` 不会反向覆盖 `Opening` 或 `Error`。全部场景的手动确认仍待完成。

审查补充：切换到其他导航页时，本地页的 `hideEvent()` 调用 `Close()`，使常驻的 `QStackedWidget` 页面离开后也能停止声音并清空状态；重新进入从 `Idle` 开始。首帧预览只对 `hasVideo()` 的文件起播，纯音频加载后等待用户点击“播放”。加载期间点击“停止”会取消当前媒体；`InvalidMedia` 兜底也覆盖加载成功后开始预览时发生的无效媒体。打开不存在的文件时会停止并释放此前的媒体源。错误或加载导致滑块禁用时，拖动标记和按下状态会清除，避免下一个文件的时间轴受影响。这些分支已通过 Debug 编译，运行场景仍需手动确认。

剩余限制：音量使用线性刻度，未使用 `QAudio::convertVolume()` 的对数映射，低音量段的听感调节不够细腻；填充方式为编译期固定值；`Open()` 时不会重置倍速与音量，二者是按播放器而非按文件保存的。

最终验收需在完整客户端确认：打开文件、播放、暂停、停止、视频显示、进度显示、Seek、音量、倍速和中文错误提示均正常，且远程 `AVPlayer` 的自研 RTMP 播放及远控链路保持不变。
