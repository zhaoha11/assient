# 本地播放功能

状态：阶段一、阶段 2.1～2.3 和阶段 3.1 已实施，UI 修改阶段结束，本地播放状态链已经打通。当前仍未接入真正的本地文件选择、解封装、解码和播放。

## 文档目的

为 ECloudAssistant 客户端逐步增加本地媒体播放功能，并记录各阶段的目标、关键做法、验证结果和剩余工作。

## 当前 UI 阶段统一边界与注意事项

- 保留 `LocalPlayerWgt` 作为独立的本地播放器页面，不嵌入 `PullerWgt`，也不直接照搬耦合了 `SigConnection` 和远程输入事件的完整 `AVPlayer`。
- 当前各阶段只处理入口、界面、窗口和布局；暂不实现文件选择、解封装、解码、OpenGL 视频渲染、音频播放及播放控制业务。
- 不修改远程控制、设备列表、高级设置、远程监控、信令或 RTMP 数据流程。
- 播放器保留打开文件、播放/暂停、停止、进度、当前时间/总时长、音量和倍速等基础控件；暂不增加最近播放、播放列表和复杂文件信息。
- 自适应布局统一使用 Qt Layout 和 `QSizePolicy`，不使用固定坐标，也不设置固定视频尺寸。
- 每个已实施阶段都需要通过 Debug 编译、链接和 `git diff --check`；完整客户端中的导航、缩放和交互效果仍需手动验证。
- UI 阶段完成后，再单独规划本地媒体链路，并评估复用 `AVDEMuxer`、现有解码器、`OpenGLRender` 和 `AudioRender`。

## 阶段一：本地播放入口与页面切换

状态：已实施。

目标：在左侧导航的“设备列表”和“高级设置”之间增加“本地播放”，点击后切换到独立的 `LocalPlayerWgt` 页面。

关键结果：

- 菜单继续复用 `CustomWgt` 的样式和统一高亮逻辑。
- `MainWgt::slot_ItemCliked()` 继续按索引通用切换，不增加本地播放专用分支。
- 导航项与 `QStackedWidget` 保持以下对应关系：

| 页面索引 | 页面 |
| --- | --- |
| 0 | 登录页 |
| 1 | 远程控制 |
| 2 | 设备列表 |
| 3 | 本地播放 |
| 4 | 高级设置 |

验收重点：四个导航项切换正确，且任一时刻只有当前菜单高亮。

## 阶段二：本地播放器 UI

整体方向：以独立的 `LocalPlayerWgt` 承载本地播放器，先完成播放器页面和主窗口的自适应布局，再进入媒体能力阶段。

### 阶段 2.1：初步播放器界面

状态：已实施（2026-09-28）。

目标：建立“大视频区 + 一条完整控制栏”的基础播放器界面。

关键结果：

- 增加大尺寸视频占位区和未打开文件提示。
- 底部统一放置进度、时间和全部基础播放控件。
- 沿用现有深色渐变风格，控件保持扁平、紧凑，并补充禁用与键盘焦点状态。
- 该阶段最初保留的顶部标题和说明，已在阶段 2.2 中移除。

验证：Debug 编译、链接通过；600×510 独立页面预览无溢出，UI 审查结论为 `ship`。

### 阶段 2.2：全尺寸播放器布局

状态：已实施（2026-09-28）。

目标：去掉页面介绍区域，让视频内容占据进度条以上的全部可用空间。

关键结果：

- 删除顶部“本地播放”标题和说明。
- 页面根布局取消多余外边距和区域间距。
- 视频区域使用 `QSizePolicy::Expanding` 和布局伸展因子自动扩展。
- 进度条紧贴视频区，操作栏贴紧页面底部，并保留阶段 2.1 的全部基础控件。
- 空状态下的视频区和控制栏使用透明背景，页面复用 `RemoteWgt` 的红棕到青绿色渐变。

验收重点：页面变化时视频区自动获得剩余空间，进度和控制区域保持在底部且无重叠、裁切或溢出。

验证：Debug 编译、链接通过；完整客户端中的手动布局检查待完成。

### 阶段 2.3：无边框主窗口缩放与自适应布局

状态：已实施（2026-09-28）。Debug 编译、链接与 `git diff --check` 通过；四边四角缩放、光标和布局自适应效果待在完整客户端中手动验证。

实施结果补充：

- 缩放命中通过应用级事件过滤器实现：递归开启主窗口及子控件的鼠标追踪，过滤器命中四边/四角后调用 `QWindow::startSystemResize()` 交给系统原生缩放，并消费该次按下事件以避免同时触发标题拖动。
- 按钮区域保持优先：命中最小化/关闭等按钮时不做缩放命中；最大化状态下禁用缩放命中。
- 主窗口初始尺寸与最小尺寸均为 800×540；`TitleWgt` 固定高度 30、`ListInfoWgt` 与导航列表固定宽度 200；`MainWgt`、`QStackedWidget`、各页面（登录、远程控制、设备列表、高级设置、本地播放）改为 `QSizePolicy::Expanding` 随窗口填充。

目标：保留 `Qt::FramelessWindowHint`，把当前固定尺寸主窗口改为可从四边和四角拖拽缩放的自适应窗口，并让本地播放器视频区随窗口同步扩展。

关键做法：

1. 顶层窗口取消 `setFixedSize()`，改为初始尺寸和最小尺寸。
2. 增加上、下、左、右及四个角的缩放命中和对应鼠标光标，并避免与现有标题栏拖动、最小化和关闭操作冲突。
3. 左侧导航保持固定宽度，高度随主窗口变化。
4. 右侧 `MainWgt`、`QStackedWidget` 和页面使用 Layout 与 `QSizePolicy::Expanding` 填充剩余空间。
5. `LocalPlayerWgt` 视频区获得新增空间，底部进度与操作区域只占自身所需高度。

验收重点：

- 四边和四角均可平滑缩放，光标方向正确，窗口不小于规定的最小尺寸。
- 左侧导航宽度不变，右侧内容和当前页面实时填满剩余空间。
- 本地播放器视频区随窗口扩展，底部控件位置稳定。
- 页面切换、导航高亮和现有标题栏操作保持正常。

## 阶段三：本地播放逻辑

职责边界：`AVPlayer` 只负责远程播放和远程控制，`LocalPlayer` 只负责本地文件播放，两者最终通过 `PlayerCore` 共享解封装、解码、音视频渲染、播放线程、状态和 PTS 同步能力。

目标结构：

```text
PullerWgt -> AVPlayer -> SigConnection -> RTMP 地址 -> PlayerCore
LocalPlayerWgt -> LocalPlayer -> 本地文件路径 -> PlayerCore
```

计划目录：

```text
ECloudAssistant/
├─ Player/
│  ├─ PlayerCore.h/.cpp      # 后续抽取公共播放核心
│  ├─ LocalPlayer.h/.cpp     # 本地播放控制
│  └─ Player.pri
├─ Puller/UI/AVPlayer.h/.cpp # 远程播放与远控
└─ UI/center/LocalPlayerWgt.h/.cpp
```

阶段三不再向 `AVPlayer` 增加 `OpenLocal()`、`PlayLocal()` 等本地接口。公共核心按实际媒体能力逐步抽取，不提前创建没有行为的 `PlayerCore` 空壳。

### 阶段 3.1：LocalPlayerWgt 与 LocalPlayer 状态链

状态：已实施（2026-09-29）。

目标：新建独立 `LocalPlayer`，打通 `LocalPlayerWgt → LocalPlayer` 的命令通路和状态通知，先确立本地与远程播放的职责边界。本任务不输出真实音视频。

关键做法：

1. 新建 `Player/LocalPlayer`，提供空闲、打开中、播放、暂停、停止和错误状态，以及播放、暂停、停止命令。
2. `LocalPlayerWgt` 只发送命令并按统一状态更新控件，不直接操作媒体组件。
3. `AVPlayer` 保持纯远程职责，不包含本地构造、状态或控制接口。
4. 本阶段不抽取 `PlayerCore`；等接入真实媒体能力时再从现有远程链路中逐步抽取。

验收重点：

- `LocalPlayerWgt` 的播放、暂停和停止命令能够到达 `LocalPlayer`，状态变化能够返回页面。
- 页面控件状态只由统一播放状态驱动，不在多个槽函数中各自维护互相冲突的布尔值。
- `AVPlayer` 中不存在本地播放接口，本地命令不会进入信令、RTMP 或远控链路。
- Debug 编译、链接和状态转换检查通过，但本阶段不宣称已经能够打开或播放本地媒体文件。

后续任务：根据实际播放调用链抽取 `PlayerCore`，再为 `LocalPlayer` 接入 `OpenFile(path)`、Seek、音量、倍速以及真实解封装和播放能力。

实施结果：已新增独立 `Player/LocalPlayer`，由它持有 `Idle / Opening / Playing / Paused / Stopped / Error` 状态并接收播放、暂停、停止命令。`LocalPlayerWgt` 直接持有 `LocalPlayer`；此前临时加入 `AVPlayer` 的本地构造、状态和命令已全部移除。

验证：qmake 重新生成工程后，Qt 6.10.1 MinGW Debug 完整编译链接通过；独立 `LocalPlayer` 状态探针验证空闲态不能直接播放，以及 `Stopped → Playing → Paused → Stopped` 的通知顺序。尚未进行本地媒体运行测试或远程 RTMP 回归测试。
