# 本地播放功能

状态：阶段一已实施（2026-09-28）：本地播放入口、`LocalPlayerWgt` 占位页面和导航切换已落地，Debug 编译链接通过；剩余验收为手动逐项切换四个导航项并确认登录及原有页面不受影响。后续阶段尚未开始，本阶段不包含媒体播放能力。

## 文档目的

为 ECloudAssistant 客户端增加本地媒体文件播放功能，使用户能够在客户端内选择并播放本地文件。本文件用于持续记录各阶段的目标、实施范围、数据流程、验证结果和剩余限制。

当前只确定功能方向，不预先假设支持的封装格式、音视频编码格式、播放控制项、界面入口或现有拉流链路的复用方式；这些内容在后续实施计划中逐项确认。

## 阶段一：本地播放入口与页面切换

### 阶段目标

在当前左侧导航栏中，于“设备列表”和“高级设置”之间新增“本地播放”菜单项。点击该菜单项后，主界面切换到新建的 `LocalPlayerWgt` 页面；菜单外观及选中高亮继续复用现有 `CustomWgt` 和 `ListInfoWgt::HandleItemSelect()` 逻辑。

本阶段只搭建 UI 页面和导航切换链路，不赋予页面实际的本地媒体播放能力，也不修改远程控制、设备列表和高级设置的业务逻辑。

### 现有结构与索引约束

当前 `ListInfoWgt::HandleItemSelect()` 将导航项索引加 1 后发送给 `MainWgt`，因为 `QStackedWidget` 的索引 0 为登录页。新增页面后，导航项和页面必须保持以下顺序：

| 页面索引 | 页面 |
| --- | --- |
| 0 | 登录页 |
| 1 | 远程控制 |
| 2 | 设备列表 |
| 3 | 本地播放 |
| 4 | 高级设置 |

插入“本地播放”时，需要同时调整导航项顺序和 `QStackedWidget` 页面顺序，避免“高级设置”仍指向旧索引而切换到错误页面。

### 实施计划

1. 在 `ListInfoWgt` 中创建新的 `CustomWgt` 菜单项，显示文本“本地播放”，并放在“设备列表”和“高级设置”之间。
2. 通过现有 `setImageAndText()` 配置菜单的普通和高亮状态，继续由 `customWgts_` 与 `HandleItemSelect()` 统一维护选中样式，不为本地播放单独增加高亮分支。
3. 新建 `LocalPlayerWgt` 页面类，页面尺寸和基础样式与现有主功能页面保持一致。本阶段页面只作为“本地播放”的占位界面，不添加媒体相关操作。
4. 在 `MainWgt` 中创建 `LocalPlayerWgt`，并将其插入设备列表页和高级设置页之间，使其位于 `QStackedWidget` 索引 3；高级设置页相应顺延到索引 4。
5. 保留 `MainWgt::slot_ItemCliked()` 现有的通用索引切换方式，不针对本地播放增加特殊判断。
6. 将 `LocalPlayerWgt` 的头文件和源文件加入 `UI/UI.pri`。若新增专用菜单图标，则通过现有资源系统提供普通和高亮两种状态，不修改 `CustomWgt` 的实现方式。

### 本阶段明确不做

- 不实现本地文件选择、文件路径解析或播放记录。
- 不引入或调用 FFmpeg，不实现解封装、解码、音视频渲染和音画同步。
- 不实现播放、暂停、停止、进度条、跳转、音量等控制功能。
- 不修改远程控制、设备列表和高级设置页面的业务处理逻辑。
- 不调整现有通信、RTMP 拉流或远程控制链路。
- 不借本阶段重构现有导航结构或其他无关代码。

### 验收标准

1. 左侧导航顺序为“远程控制 → 设备列表 → 本地播放 → 高级设置”。
2. 点击“本地播放”能够显示 `LocalPlayerWgt`，点击其他菜单仍能进入原有对应页面。
3. 任一时刻只有当前选中的菜单项处于高亮状态，切换行为与现有菜单一致。
4. 本地播放页能够正常显示，但不存在文件选择、解码或播放行为。
5. 登录流程以及远程控制、设备列表、高级设置的原有功能不受影响。
6. 新文件加入工程后重新运行 qmake，Debug 配置编译、链接通过，并手动完成四个导航项的逐项切换验证。
